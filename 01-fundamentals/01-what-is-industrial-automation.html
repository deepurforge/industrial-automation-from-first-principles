01

The Problem Automation Solves

Before any technology existed, every industrial process was run by a human watching a physical quantity and reacting to it by hand — observe, judge, act, repeat, without a break and without a mistake.

That works, but it has hard limits: humans get tired, can't watch hundreds of variables at once, can't react in milliseconds, and can't work in toxic or extreme environments. Industrial automation exists to remove these limits — not by eliminating the logic of observing and reacting, but by moving that logic into a machine that can do it faster, longer, and more consistently than a person can.

02

What Is Automation?

ISA (International Society of Automation) defines automation as the creation and application of technology to monitor and control the production and delivery of products and services.

NIST describes an Industrial Control System (ICS) as a combination of electrical, mechanical, hydraulic, and pneumatic components working together toward an industrial objective.

TermWhat it meansWhat it does NOT mean
MonitorContinuously sense real-world stateJust "having a sensor installed"
ControlDecide + execute a corrective actionJust "having an output wire"
03

Automation vs Mechanization

Mechanization replaces human muscle — a conveyor belt moves boxes instead of a person carrying them. It removes physical effort, but a human still decides when to start, stop, or adjust it.

Automation replaces human judgment and reaction — a level sensor detects the tank is full and the system decides, without a person, to close the valve.

If a motor replaces human muscle, that's mechanization. If a sensor detects a condition and a controller automatically decides what to do about it, that's automation.

Sensors — How the System Knows

A sensor converts a physical quantity into a signal the rest of the system can use. For the tank, an ultrasonic sensor might measure the distance to the water surface.

Physical quantity (water level in cm)
       ↓
Physical effect (e.g. ultrasonic echo delay)
       ↓
Electrical signal (e.g. 4-20 mA)
       ↓
Value the controller can read

A controller can never be more accurate than the information it's given — this is why sensor accuracy and response time are critical specs in real industrial design.

07

Decision and Control

The controller takes the sensor's information and decides what action to take. For the tank:

IF level < 20%  → turn pump ON
IF level > 90%  → turn pump OFF
ELSE            → do nothing

This simple on/off logic is called bang-bang control. Real controllers often use more refined logic like PID, but the role stays identical: take input, apply a decision rule, produce an output.

08

Actuation — How the System Acts

An actuator physically changes the process based on the controller's decision — the pump is the tank's "hands."

Controller decision: "turn pump ON"
       ↓
Output signal sent (e.g. 24V DC to a relay)
       ↓
Relay energizes → pump motor receives power
       ↓
Pump physically moves water → level rises

This is where an electrical decision becomes a physical event — watch it happen live in the panel at the top of this page.

09

Feedback

Feedback closes the loop — it's how the system verifies whether its own action actually worked. Without it, a system is "open-loop": it acts blindly, with no way to know if a valve is stuck or a pump has failed.

Sensor reads new level
→
Compare to setpoint
→
Adjust actuator
→
Process changes
10

Where the PLC Fits

A PLC (Programmable Logic Controller) is the industrial-hardened computer that most commonly plays the "Controller" role.

  1. Sensor → Input Module: the sensor outputs a real signal — often 4-20 mA or 24V DC on/off.
  2. Input Module: filters, isolates, and converts the signal (A/D conversion) so the CPU can read it as a number.
  3. CPU scan cycle: reads all inputs → executes the logic program → writes all outputs, many times per second.
  4. Output Module → Actuator: the decided value is converted back into a real signal, e.g. 24V DC to a relay.
  5. Actuator → Process: the pump moves, and the real-world level changes.

First-Principles Mental Model

Strip away every brand name and acronym, and industrial automation is just this:

A system that continuously knows the true state of a physical thing, compares that state to what it should be, and takes action to close the gap — without needing a human to do it manually, every time.
  • The sensor answers: "What is actually happening right now?"
  • The controller answers: "What should happen, and how do we get there?"
  • The actuator answers: "How do we physically make that happen?"
  • Feedback answers: "Did it actually work?"
14

Key Takeaways

  • Automation = monitor + control, applied by technology instead of a human.
  • Mechanization replaces muscle; automation replaces judgment and reaction.
  • Every automated system is built from: Process → Sensor → Controller → Actuator → back to Process.
  • A PLC is one specific, industrial-hardened implementation of the "Controller" role.
  • Feedback is what makes a system self-correcting instead of blind.
  • Real factories stack many loops: Process → I/O → PLC → Network → SCADA → Historian/MES → ERP.
